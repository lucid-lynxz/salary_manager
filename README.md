# 社区工资单 · 邮箱合并工具

一个面向非技术人员的网页版工具，用于将社区人员工资单与邮箱信息按 **社区 + 姓名** 合并，校验邮箱有效性后持久化到本地数据库，支持按姓名模糊查询、按月份追溯历史工资、导出合并结果 Excel，并可通过多发件人账号将工资单邮件批量发送到个人邮箱。

---

## 一、设计思路

### 1.1 为什么做这个工具

社区每月发放工资条时需要把工资数据发送到个人邮箱。原始数据分为两类：

- **工资表**：包含社区、姓名、应发工资、五险一金、实发工资、银行账号等。
- **邮箱表**：包含社区、姓名、邮箱。

人工合并存在以下问题：

- 邮箱可能包含空格、换行、缺少 `@`、重复或无效格式，直接发送会失败。
- 不同社区可能出现同名人员，仅用姓名合并会导致串邮。
- 工资表表头复杂（多行表头、合并单元格、冗余合计行），直接读取容易错位。
- 工资每月一发，需要保留历史以便复查。

因此设计了本工具：通过网页向导完成导入，自动清洗和校验邮箱，按 `社区 + 姓名` 精确合并，并将结果写入 SQLite 数据库，后续可随时搜索和查看历史。

### 1.2 数据模型

数据库 `salary.db` 包含三张表：

| 表名 | 作用 |
|------|------|
| `salary_imports` | 记录一次导入的年月、文件名、导入时间。同一 `year + month` 唯一，重复导入会覆盖旧数据。 |
| `persons` | 记录某次导入中合并后的人员基础信息：`社区`、`姓名`、`邮箱`、`邮箱状态`、`邮箱问题`。同一导入内 `社区 + 姓名` 唯一。 |
| `salary_records` | 记录人员的完整工资明细，以 JSON 保存原始行数据，并额外抽取 `应发工资`、`代扣合计`、`实发工资`、`银行账号` 等常用字段方便查询。 |
| `sender_emails` | 邮件发件人账号：SMTP 服务器、端口、账号、授权码、备注别名、启用状态。批量发送时按账号轮换并做单账号 10 秒限速。 |

### 1.3 关键处理逻辑

#### 表头合并

工资表常使用多行表头 + 合并单元格（例如“代扣款项”下方细分为“住房公积金”“养老保险”等）。读取时：

- 第一行表头做横向填充，用于识别合并单元格的父标题。
- 后续行使用原始值，避免子标题横向“污染”其他列。
- 若某列同时存在父标题和子标题，优先使用子标题。
- 同名列自动加 `(2)`、`(3)` 后缀，防止原始行数据被同名表头覆盖。

#### 数据范围

自动跳过以下行：

- 空行
- 包含“计”“合计”“审核”等关键字的汇总/备注行

用户可在界面中指定：

- 表头所在行（可多行，Excel 行号，1-based）
- 数据起始行、结束行（结束行留空表示到末尾）
- 数据结束列（留空表示不限制；支持 Excel 字母如 `Z`、`AA` 或列号如 `26`）

#### 年月识别

导入工资表时，系统会尝试从文件名（如 `2025.01`、`2025-01`、`2025年1月`）或表格前 5 行文本中提取年月。提取成功会在第三步自动预填；若未识别或识别错误，用户可手动修改年份和月份。

#### 邮箱校验

导入邮箱表时会自动：

1. 去除空格、换行、制表符。
2. 将全角 `＠`、` at ` 等替换为 `@`。
3. 转小写。
4. 检查是否为空、是否含 `@`、是否符合正则格式。
5. 检查是否重复（全局重复，即不同人员使用同一邮箱）。

校验结果分为：

- `valid`：有效
- `invalid`：无效（会列出具体问题）
- `missing`：工资表中有该人员，但邮箱表中未找到

对于检测到的异常邮箱，第二步的校验区会按类型分组列出，每条记录都支持三种处理：

- **确认**：接受当前邮箱继续导入（例如确认某邮箱确为多人共用）。修改过邮箱后需重新确认。
- **修改**：就地编辑。重复邮箱/格式异常可改邮箱，「社区+姓名」重复可改社区或姓名。改动实时同步到上方文件预览，并在「邮箱修改记录」中留痕（含行号）。
- **删除**：移除该条邮箱记录（有二次确认弹框），对应人员在合并时会变成「未匹配」；删除后可在「已删除的邮箱记录」中撤销。

三类异常分别是：**重复邮箱**（同一邮箱被多人使用，支持整组一键确认）、**其他邮箱问题**（为空/缺少 `@`/格式无效）、**社区+姓名重复**（必须改姓名或删掉一条才能继续，因为合并以该组合为唯一键）。所有异常处理完毕前，「下一步：确认导入」保持禁用。

邮箱覆盖按 **Excel 行号** 存储（而非「社区+姓名」），因此重名人员的两条记录可以分别修改、互不覆盖。

#### 合并规则

以 `社区 + 姓名` 作为唯一键。工资表中的每一条记录都会去邮箱表中查找对应人员：

- 找到且邮箱有效：写入数据库。
- 找到但邮箱无效：仍会写入，但标记邮箱状态为 `invalid`，并记录问题，方便后续人工修正。
- 未找到：标记为未匹配，导入结果中会列出名单。

#### 年月处理

- 自动从工资表前 5 行中匹配 `2025年1月`、`2025-01`、`2025/01` 等格式。
- 若未检测到明确日期，界面会提示用户手动选择年月。

## 二、快速开始

### 2.1 一键启动（推荐）

项目已提供 `start.sh` 和 `stop.sh` 脚本，首次运行会自动创建虚拟环境并安装依赖。脚本已适配 Windows（Git Bash / MINGW64）与 Unix 环境，会自动检测操作系统并使用对应的 Python 路径、虚拟环境激活方式和端口清理命令（Windows 下使用 `netstat + taskkill`，Unix 下使用 `lsof`）。

```bash
cd /path/to/salary_manager
./start.sh
```

> **Windows 注意**：请在 Git Bash 中执行 `./start.sh`。若 `code` 命令在 Git Bash 下报错（路径被 Anaconda 环境篡改），改用 PowerShell 或直接从 VS Code 打开文件即可。

> **Linux / 银河麒麟注意**：双击 `.sh` 文件在多数 Linux 桌面（含银河麒麟）不会打开终端运行，需在文件管理器「属性 → 权限」勾选可执行，或在终端里执行 `bash start.sh`。脚本会输出环境检测信息：缺少 `python3` / `python3-venv` 时给出对应发行版的安装命令（麒麟/UOS/Deepin 用 `sudo apt install python3 python3-venv python3-pip`）；系统未装 `lsof` 时自动退回 `ss` 检测端口。新版「打包项目」生成的 zip 已为 `start.sh` / `stop.sh` 保留可执行权限（0o755），解压后可直接运行。

启动成功后会自动打开默认浏览器，并输出访问地址：

```
启动成功！正在打开浏览器: http://127.0.0.1:5000
```

停止服务：

```bash
./stop.sh
```

### 2.2 手动启动（可选）

如果希望手动控制虚拟环境，也可以按传统方式启动：

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python app.py
```

首次运行会自动创建 `salary.db` 数据库和 `uploads/` 上传目录。

### 2.3 导入数据

1. 点击“导入数据”标签页。
2. **第一步**：选择工资表 Excel，选择正确的 Sheet，确认/调整表头行和数据范围，点击“解析预览”。
   - 表头所在行支持多行，可填写 `3,4`、`3-4` 或混合形式如 `2,4-6`，均为 Excel 行号（从 1 开始）。
   - 修改表头所在行后，**数据起始行**会自动跟随表头最大行号 + 1（例如表头填 `3,4`，数据起始行自动变为 `5`）。
   - 文件预览表格会显示 **Excel 行号**（左侧）和 **列字母 + 数字序号**（表头）。默认显示表头 + 前 5 行数据 + 后 5 行数据；如果数据行数 ≤ 10 行则直接全部显示；超过 10 行时中间用省略行提示，方便你对照原始文件检查首尾数据。
   - 点击 **“全量”** 按钮可切换到全量预览模式，显示全部数据行并启用分页（支持 10 / 20 / 50 / 100 / 500 条每页，默认 20 条）。全量模式下可冻结「社区」「姓名」列和表头，方便横向/纵向滚动查看大表。
   - 预览中的日期时间（如 `2005-03-01 00:00:00`）会自动简化为日期部分。
3. **第二步**：选择邮箱表 Excel，同样确认范围后点击“解析并校验邮箱”。
   - 若出现邮箱问题，会列出具体行号、人员、原始邮箱和清洗后的邮箱，以及问题原因。
   - 同样支持「全量」预览和分页，列冻结行为与工资表一致。
   - 若本月没有新的邮箱表，可点击 **“跳过邮箱表 →”**：确认后所有员工邮箱留空，并自动进入第三步（无需再手动点“下一步”），在第三步用历史邮箱自动填充。
4. **第三步**：确认工资单年月，预览合并结果，点击“执行导入”。
   - 进入第三步时，系统会自动按 **社区 + 姓名** 合并工资表与邮箱表，生成合并预览表（邮箱列置于最后）。
   - 预览表同样支持「全量」分页、冻结社区/姓名列与表头。
   - 点击 **“仅看未匹配”** 按钮可筛选出邮箱为空的人员，方便人工复查；存在未匹配记录时页面会自动开启该筛选。
   - 邮箱为空的人员行内可直接输入邮箱，或点击 **“历史”** 按钮从该「社区+姓名」的历史邮箱中选择填入。
   - 点击 **“🔍 一键查找历史邮箱”** 可批量为所有未匹配人员按「社区+姓名」查找最近一次导入中的邮箱并自动填入（全部补齐后自动退出“仅看未匹配”筛选）。
   - 存在未匹配记录时，点击“执行导入”会先弹出二次确认。
   - 导入完成后会显示统计：工资记录数、成功匹配数、未匹配数、邮箱异常数；随后自动跳转到「导入历史」标签页，同时导入向导重置回第一步待导入状态，可直接开始下一个月。

### 2.4 查询人员

1. 切换到“人员查询”标签页。
2. 在“按姓名模糊搜索”输入框中输入关键字（例如“张”），系统会自动弹出下拉建议，列出匹配人员：
   - 每行显示：社区、人名、岗位、调资居龄、岗位工资等级年限起算时间。
   - 若选择了具体月份，则下拉中只显示该月份的数据；不选择月份时默认取**最新月份**的数据。
3. 若模糊匹配只有一条候选项，会自动触发搜索；否则点击下拉中的某条人员，也会以精确搜索展示结果。
4. 也可以直接点击“搜索”按钮：
   - 若输入了姓名，默认展示该人员所有月份的工资记录表格。
   - **若未输入姓名，则等价于列出最新月份的全部人员**。
5. 月份下拉框选择“最新数据”表示使用最近一次导入的月份；选择“全部数据”则不按月份过滤；选择具体年月则按该月份过滤。

### 2.5 管理导入历史

切换到“导入历史”标签页，可查看所有已导入的年月、文件名和导入时间。

- **双击**某条历史记录可弹出该次导入的完整数据明细表，邮箱列置于最后，支持分页（10 / 20 / 50 / 100 / 500）、冻结社区/姓名列与表头。
- 明细表中可**双击邮箱单元格**直接编辑（带格式校验，取消时智能恢复原值），也可逐人发送工资单邮件。
- **“导出”**：将该次导入的工资+邮箱合并数据导出为 Excel（保持工资表原始列顺序，末尾追加邮箱列，冻结首行前三列、自动列宽），下载后保存于 `exports/` 目录。
- **“发送工资单邮件”**：选择发件人账号后批量发送，弹框显示进度条（已发送 X/Y），完成后可查看逐人发送结果明细；失败记录支持“仅重发失败”。同一月份重复导入会重置发送状态。
- 点击“删除”可移除某次导入及其全部人员和工资数据（有二次确认）。
- **“统计”**：页面顶部的统计按钮将所有导入汇总为一张统计表（按年月倒序，每行一个月，第一列为年月）：
  - 数值列：总人数、应发工资合计、代扣合计、实发工资合计、岗位工资合计，点击列头的 📈 可查看该列的跨月趋势折线图（含最小/最大/中位数/平均/求和/标准差汇总，悬停数据点显示较上月的变化绝对值与百分比）。
  - 变化列（与下一行即上月对比）：邮箱空白、人员变更（+新增/-减少）、岗位工资变更、邮箱变更、银行账号变更；点击单元格弹出二层明细框（社区+姓名，岗位工资含上月/本月/相差，邮箱与账号含上月/本月原值），支持按社区/姓名关键词实时筛选并显示匹配条数。首次导入无对比基准，显示“—”。

### 2.6 发件人管理

切换到“发件人管理”标签页，维护用于发送工资单邮件的 SMTP 账号：

- 支持添加多个发件人（服务器、端口、账号、授权码、可选备注别名），QQ 邮箱需使用授权码而非登录密码。
- 每个账号可**启用/停用**，批量发送仅在启用账号中轮换，且**同一账号两次发送间隔不少于 10 秒**以降低垃圾邮件风险。
- **“测试”**：发送前可自定义收件人和内容发送测试邮件，验证 SMTP 配置是否正确。
- 明细弹框与批量发送弹框均显示“已发送 X/Y”进度与失败明细。

### 2.7 系统控制

页面右上角提供一组系统控制按钮：

- **主题**：支持“跟随系统 / 浅色 / 深色”三种模式，默认“跟随系统”，选择后自动保存到浏览器本地。
- **打开项目**：使用系统默认方式打开项目所在目录。
- **打包项目**：将项目打包为 zip 并打开 `packages/` 目录，支持三种模式：
  - **仅代码**：不包含数据库和运行环境，体积最小。
  - **带数据库文件**：包含 `salary.db`，方便迁移数据。
  - **带运行环境**：包含代码、数据库和 `venv/`，但**不能保证跨平台运行**（venv 与创建时的操作系统、Python 路径强相关）。
- **停止服务**：调用 `stop.sh` 停止当前 Flask 服务。

## 三、API 概览

| 接口 | 方法 | 说明 |
|------|------|------|
| `/` | GET | 主页面 |
| `/api/preview` | POST | 上传 Excel，返回 Sheet 列表、预览、自动检测的表头行和年月 |
| `/api/sheet-preview` | POST | 切换 Sheet 后重新预览 |
| `/api/download/<file_id>` | GET | 下载已上传的原始文件 |
| `/api/parse-config` | POST | 按指定范围解析记录，返回列名、建议列映射、记录数、邮箱校验报告 |
| `/api/import-preview` | POST | 按 社区+姓名 合并工资表与邮箱表，返回合并后的二维数据（不写入数据库），供第三步预览；支持邮箱表跳过 |
| `/api/import` | POST | 执行工资表与邮箱表的合并导入；邮箱表可标记 `skipped` 全部留空 |
| `/api/history-emails` | GET | 查询某「社区+姓名」的历史邮箱列表（行内“历史”按钮用） |
| `/api/historical-emails` | POST | 批量按「社区+姓名」查找最近一次导入的邮箱（“一键查找历史邮箱”用） |
| `/api/months` / `/api/communities` | GET | 已导入的年月 / 社区列表 |
| `/api/search-suggest` | GET | 按姓名模糊搜索，返回下拉建议（含岗位、调资居龄、起算时间摘要） |
| `/api/search` | GET | 按姓名模糊搜索，可选年月过滤 |
| `/api/person/<id>` | GET | 获取单个人员的详细历史记录 |
| `/api/person/<id>/email` | POST | 修改某人员的邮箱 |
| `/api/persons-by-import` | GET | 按导入批次获取人员列表 |
| `/api/imports` | GET | 获取导入历史列表 |
| `/api/import-stats-table` | GET | 所有导入的统计汇总表（每月一行：汇总值 + 与上月的变化明细，统计弹框用） |
| `/api/import/<id>` | DELETE | 删除指定导入记录 |
| `/api/import/<id>/records` | GET | 获取某次导入的完整明细（弹框表格用） |
| `/api/export-import/<id>` | POST | 将某次导入的工资+邮箱合并数据导出为 Excel |
| `/api/download-export/<export_id>` | GET | 下载导出的 Excel 文件 |
| `/api/write-back-salary` / `/api/write-back-email` | POST | 将校验区修改写回原始 Excel 文件（仅覆盖数据行，保留表头结构） |
| `/api/sender-emails` | GET / POST | 发件人列表 / 新增发件人 |
| `/api/sender-emails/<id>` | PUT / DELETE | 修改 / 删除发件人 |
| `/api/sender-emails/<id>/toggle` | PATCH | 启用 / 停用发件人 |
| `/api/sender-emails/<id>/test` | POST | 发送测试邮件验证 SMTP 配置 |
| `/api/check-senders` | GET | 检查是否存在可用的启用发件人 |
| `/api/import/<id>/send` | POST | 对某次导入批量发送工资单邮件 |
| `/api/import/<id>/send-details` | GET | 查询某次导入的发送进度与逐人结果 |
| `/api/import/<id>/send-person/<person_id>` | POST | 重发单人工资单邮件 |
| `/api/send-salary-emails` | POST | 按年月批量发送工资单邮件 |
| `/api/email-send-status` / `/api/reset-email-send-status` | GET / POST | 查询 / 重置发送状态 |
| `/api/user-config` | GET / PUT | 读取 / 保存用户界面配置 |
| `/api/open-project-dir` / `/api/package-project` / `/api/stop-service` | POST | 打开项目目录 / 打包项目 / 停止服务 |

## 四、注意事项

- 本工具使用 Flask 内置开发服务器，适合本地办公场景。如需多人长期使用，建议部署到正式 WSGI 服务器（如 Gunicorn）。
- `uploads/`、`exports/` 和 `salary.db` 已加入 `.gitignore`，不会被提交到 git。
- `sender_emails` 表中保存了发件人 SMTP 授权码，仅存于本地 `salary.db`，打包“带数据库文件”时请注意保密。
- `*.xlsx`（含 `assets/` 下的示例和测试文件）已加入 `.gitignore`，不会被提交。需要时可通过 `generate_test_data.py` 或 `generate_large_test_data.py` 重新生成。
- 同一月份的工资单再次导入会覆盖旧数据，避免重复人员。
- 若工资表结构变化（例如新增列），原始数据仍以 JSON 完整保存，常用字段的抽取依赖列名模糊匹配，建议在导入后检查查询结果。
